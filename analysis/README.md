# `analysis/`

Notebooks for analysing run results.

Notebooks are not the pipeline — they read what the pipeline wrote. Keep fitting
logic in `core/` so a notebook and a script cannot disagree about what a direction
is.

## What is here

| file | what it is |
| --- | --- |
| `results_notebook.ipynb` | **the outline.** 13 code cells, one line each: prose, then a call into `nbsections`. Read-only over `outputs/`; no model, GPU, network or R2. |
| `nbsections.py` | **one function per section** — all loading, computing, table-building and wording. This is where you edit what a section says. |
| `nbtools.py` | artefact loading, the report accumulator, markdown tables, script classification, the per-phase field extractors, the tiered GATE A statistic. |
| `nbfigures.py` | plot builders; each returns a bare matplotlib figure and knows nothing about the report. |
| `zh_en_glossary.py` | hand-written Chinese↔English matching data. **Not pipeline output** — the only non-derived input; see its docstring for the pre-commitment protocol. |
| `RESULTS.md` | generated by the notebook — every table, a reference to every figure, paste-ready. **Do not edit by hand.** |
| `VERIFICATION.md` | audit trail: each claim sourced to a file, with a runnable command that re-derives it and an attack-surface section. |
| `figures/` | figures the notebook generates. Pipeline-generated figures stay in `outputs/` and are referenced in place. |

## Where to make a change

| you want to change | edit |
| --- | --- |
| what a section concludes, or a table in it | the matching function in `nbsections.py` |
| how a figure is drawn | `nbfigures.py` |
| how tables render, or how artefacts load | `nbtools.py` |
| the order of the argument, or the framing prose between sections | the notebook's markdown cells |

`nbsections` functions run **once, in order**, passing work forward through the handles
listed in its `SHARED` dict. Re-running one out of order will not crash — every body is
wrapped in `Report.guard` — but it may report artefacts as missing. Restart and run all
if in doubt.

Three invariants worth preserving:

* **Anything a reader should see goes through `Report`** (`R.md`, `R.table`, `R.fig`).
  A plain markdown cell renders in Jupyter and then silently vanishes from `RESULTS.md`.
* **`R.fig()` requires a `how_to_read` and a `what_it_shows`.** It writes a `TODO`
  marker into the output if either is missing, and `S.export()` asserts that count is
  zero — so an unexplained plot fails the build rather than shipping.
* **`Report.guard` swallows exceptions by design.** That keeps a missing artefact from
  killing the run, but it also means a refactor can silently blank a section. After any
  change, check that `RESULTS.md` contains no `Skipped --` lines.

Run it under conda `base` (the system `python3` has no packages):

```bash
~/miniconda3/bin/python -m jupyter nbconvert --to notebook --execute \
    --inplace --ExecutePreprocessor.kernel_name=base analysis/results_notebook.ipynb
```

Loading a finished run:

```python
from core.activation_store import ActivationStore
from core.directions import DirectionSet
from core import plotting

run = "outputs/qwen2.5-32b_10emo_all-layers"

directions = DirectionSet.load(f"{run}/results/directions")
store = ActivationStore(f"{run}/activations")

directions.emotions          # emotion order for every matrix
directions.layer_indices     # layers available
v = directions.direction("angry", layer=32)     # (hidden,), unit norm

# Held-out activations for one split, one layer
rows = store.subset(source="emotion", splits=["test"])
acts = store.load_layer(32, rows)                # (n, hidden) float32
scores = directions.score(acts, layer=32, mode="centered_dot")   # (n, n_emotions)

plotting.apply_style()       # same validated palette as the pipeline plots
```

`store.index` is the full per-example index (example id, emotion, topic, split,
token counts, chunk location). `store.skipped()` returns anything excluded during
extraction, with reasons.

Reach for `directions.matrix(layer, "direction_unprojected")` when you want to check
whether a result depends on the neutral-PC removal step.
